= 從NetApp Data Classification中的資料來源收集的元數據
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
NetApp Data Classification 會在掃描資料來源和系統時收集元資料。大多數元資料都可用，但某些屬性並非所有協定都支援。

[cols="15,25,25,25"]
|===
|  | *元資料* | *CIFS* | *NFS* 


.3+| *時間戳* | _建立時間_ | 可用的 | 不可用（Linux 不支援） 


| 上次存取時間 | 可用的 | 可用的 


| 最後修改時間 | 可用的 | 可用的 


.2+| *權限* | _開放權限_ | 如果“EVERYONE”群組有權存取該文件，則視為“對組織開放” | 如果“其他人”有權存取該文件，則視為“對組織開放” 


| _使用者/群組存取_ | 使用者和群組資訊取自 LDAP | 不可用（NFS 使用者通常在伺服器本地進行管理，因此同一個人在每個伺服器上可以有不同的 UID） 
|===
[NOTE]
====
* 資料分類不會從資料庫資料來源提取「上次存取時間」。
* 舊版的 Windows 作業系統（例如 Windows 7 和 Windows 8）預設會停用「上次存取時間」屬性的收集，因為這可能會影響系統效能。如果未收集此屬性，則基於「上次存取時間」的 Data Classification 分析將受到影響。如有需要，您可以在這些舊版 Windows 系統上啟用「上次存取時間」屬性的收集。


====


[[last-accessed-time]]
== 最後存取時間

當 Data Classification 從檔案共用中提取資料時，作業系統會將其視為存取事件，並相應地更新「上次存取時間」。掃描完成後，Data Classification 會嘗試將上次存取時間還原為原始時間戳記。如果 Data Classification 在 CIFS 中沒有寫入屬性權限，或在 NFS 中沒有寫入權限，則系統無法將上次存取時間還原為原始時間戳記。

預設情況下，Data Classification 在沒有寫入權限來還原原始時間戳記時不會掃描檔案。如果您的資料可以容忍最後存取時間不重設為原始時間戳記，請在系統設定頁面中啟用 *Scan without write permissions*。

image:screenshot_scan_missing_permissions.png["螢幕截圖顯示您可以使用的開關，即使 Data Classification 沒有正確的權限將上次存取時間還原為原始時間戳記，也可以掃描您的檔案。"]

此功能適用於本機ONTAP系統、 Cloud Volumes ONTAP、 Azure NetApp Files、 Amazon FSx for NetApp ONTAP管理和第三方檔案共用。


NOTE: 配置了 SnapLock 的 ONTAP 磁碟區具有唯讀權限，也無法將上次存取時間還原為原始時間戳記。
